# LP001 待機予定0件なら非掲載：テスト用改修（2026-10-10）

## 位置付け
- **ユーザーの決定**：LP表示対象期間に現在進行中／これから開始の有効な「待機」予定が1件以上あればカード掲載。0件ならカードごと非掲載。予定再登録で再掲載。
- **LINE WORKSの優遇は独立**：「待機してます」操作による緑表示・上位優遇と、カレンダーに待機予定が存在することを混同しない。
- **対象**：`story/mizuki/` に静的に存在する梅津1名カード、および `lp001/` にあるそのカード。複数人分の本人紐付けと順位再構成は別工程。
- **未適用**：この変更はQA用ブランチだけ。本番main、Googleカレンダー、GASデプロイ、Stripe、LINE WORKSを変更していない。

## GAS→LPデータ契約（本番にまだ存在しない。統合前の必須条件）

現在のv0.33で返される `week_slots` はLINE WORKS『終了します』後に進行中の枠が除外されるため、LPへの掲載資格の判定には使わない。

`action=status` の従来のレスポンスを壊さず、**相談員本人のGoogleカレンダーから独立抽出した**次の項目を追加する必要がある。

```json
{
  "consultant_no": "0000-3",
  "online": false,
  "week_slots": [],
  "calendar_slots": [
    {"start": "2026-10-10T20:00:00+09:00", "end": "2026-10-10T22:00:00+09:00"}
  ]
}
```

- `calendar_slots` は、当人の「待機」イベントのみ、キャンセル・終日・不正日時を除いて返す。
- 現時点で終了前の枠、または次の7日以内に開始する枠が掲載資格。開始済みでも未終了なら対象に含める。
- この配列はLINE WORKSの `online/state` によって加工しない。本人以外のイベントや非公開カレンダーIDは公開しない。
- `calendar_slots: []` は**Calendar取得に成功して有効枠が0件だった**意味に限定。取得失敗時に `[]` を返してはならない。失敗・新API未実装は欠落または別のエラー値を使う。
- `calendar_slots` が未提供の場合、テストブランチは旧LP表示をそのまま維持する。**この移行互換性は公開条件を満たすことではないため、バックエンド連携前に本番へマージしない。**

## UI（QAブランチ）

`lp001/schedule-eligibility.js` の `evaluate(calendarSlots, now, days)` が `known/eligible/count` を返す。新プロパティの有効データがある場合だけ、カードの `hidden` と `display` を更新する。

カードが0枚になった場合は、LPの「話せる人」セクションと `#people` を指す内部CTAも隠す。そのカード内のStripe購入ボタンもカードと一緒に非表示。未来予定1件を返すと再表示。

複数人への拡張時は「もっと見る」の件数も再計算すること。今の8人旧候補ページは梅津以外の待機APIが未連携であり、**全員の掲載フィルターが完成したわけではない**。
